Контекст и ТЗ

Задание

Разработать стартовую документацию Я.Трекера под ролевую модель «Бизнес-аналитик».

Контекст

Пользователем данной документации является опытный бизнес-аналитик, который впервые сталкивается с Я.Трекером. Для быстрого старта в работе ему требуется минимально необходимый набор знаний, необходимый для решения рабочих задач.

Требования заказчика

  • Часть 1. Структура раздела. Сформировать иерархическую структуру статей. Исключить избыточность, зафиксировать цели и подтемы для каждой статьи.
  • Часть 2. Ключевая инструкция. Написать полностью готовую к передаче пользователям статью «Создание задачи и основные приёмы работы с ней».
  • Ограничения. Деловой стиль без фамильярности, полная оригинальность без пересказа справки Яндекса, обязательные скриншоты с автономными текстовыми описаниями.

Анализ задачи и проектирование решения

1Подход к выполнению задания

При проектировании стартового раздела рассматривались два принципа организации материала:

  • Функциональный подход: построение документации вокруг возможностей системы — очередей, задач, статусов и других функций
  • Сценарный подход: по рабочим сценариям пользователя — обучение через выполнение типовых рабочих задач

Для стартового раздела выбран комбинированный подход: в основу положен ключевой рабочий сценарий пользователя, а остальные статьи раскрывают функциональность, необходимую для его выполнения.

Выбор очереди и инициация создания задачи

Чтобы задача попала в контекст нужной команды и получила правильный префикс (например, LK-101), её необходимо создавать внутри соответствующей очереди.

  1. На левой навигационной панели Яндекс Трекера нажмите синюю кнопку «+ Создать задачу».
  2. В левом верхнем углу выпадающего окна выберите очередь вашего проекта — LK: Личный кабинет.

Заполнение названия и базовой структуры требования

Укажите понятное название темы и внесите структурированное описание требования с помощью визуального редактора.

Совет по оформлению: Используйте визуальный редактор Трекера (панель инструментов над текстом) для форматирования списков, выделения заголовков и вставки ссылок.

Декомпозиция работы через Чек-лист (опционально)

Чек-лист позволяет аналитику разбить верхнеуровневую задачу на подшаги, контролировать промежуточный прогресс и назначать ответственных на конкретные микрозадачи.

  1. Под блоком текстового описания нажмите кнопку + Чеклист.
  2. Последовательно добавьте пункты, нажимая «Сохранить» или клавишу Enter после каждого.
  3. При необходимости укажите отдельного исполнителя и дедлайн для каждого пункта чек-листа непосредственно в его строке.
  4. Чтобы удалить лишний пункт, наведите на него и нажмите значок корзины справа.

Настройка атрибутов задачи (Правая панель)

Параметры задачи на правой панели определяют приоритеты, сроки и ответственных лиц.

  • Тип задачи: По умолчанию указано Задача (или Требование).
  • Приоритет: Выберите = Средний (или Высокий, если фича критична для ближайшего релиза).
  • Исполнитель: Введите имя системного аналитика или разработчика. Если вы сами берете задачу в работу — нажмите кнопку Назначить меня (Я).
  • Дедлайн: Укажите целевую дату завершения анализа и передачи в разработку.
  • Наблюдатели: Добавьте продакт-менеджера, тимлида разработки и QA-инженера, нажав Добавить меня или выбрав коллег из списка. Они будут получать уведомления обо всех изменениях по задаче.
  • Прикрепить файлы: Нажмите значок 📎 под описанием, чтобы приложить прототипы экранов или OpenAPI-спецификацию.

После заполнения всех атрибутов нажмите синюю кнопку «Создать задачу» внизу экрана.

Ведение коммуникации и сопровождение в комментариях

После создания задачи вся рабочая переписка, вопросы тестирования и согласования должны происходить внутри карточки задачи в блоке «Комментарии». Это создает единый информационный контур и сохраняет историю решений.

Как оставить комментарий и призвать коллегу:

  1. Прокрутите страницу задачи вниз до блока «Комментарии».
  2. В поле ввода введите текст (например: «Коллеги, подготовил спецификацию API СБП. Просьба провести ревью»).
  3. Нажмите кнопку @ Призвать под полем ввода и выберите из списка разработчика или техлида. Пользователь получит прямое уведомление и задача отобразится у него в фильтре «Ждут ответа».
  4. Для вложения артефактов нажмите Прикрепить файл (или перетащите файл прямо в окно ввода).
  5. Нажмите кнопку «Отправить».
  • Реакции: Наведите на комментарий и нажмите значок эмодзи (👍, 🚀, ✅), чтобы быстро подтвердить получение информации.

Завершение работы и закрытие задачи

По мере продвижения аналитик обновляет статус задачи на правой панели управления. Статус адресован команде: по нему коллеги понимают, чего от задачи ждать, не открывая переписку.

Основной жизненный цикл:

  1. Открыт — исходное состояние при создании задачи.
  2. В работе — работа над требованием началась: проектирование, согласование или передача в разработку.
  3. Решен / Закрыт — требование реализовано, протестировано и задеплоено.

Закрытие неактуальной задачи

Если задача создана по ошибке или планы изменились, её не удаляют, а закрывают — так в очереди остаётся история решений. Переведите задачу в статус Закрыть и выберите Резолюцию: это поле обязательное.

  • Отменено — задача создана ошибочно или функциональность отменили.
  • Дубликат — аналогичная задача уже есть в очереди.

А если задачу нужно именно удалить? Такая возможность есть, но найти её непросто: в меню действий на карточке задачи пункта удаления нет, и поиск обычно заходит в тупик именно здесь. Удаление доступно через ⟨указать путь⟩.

Пользоваться им стоит только для явного мусора — например, задачи, созданной по ошибке в две минуты жизни. Во всех остальных случаях закрытие с резолюцией предпочтительнее: удалённую задачу нельзя восстановить, а вместе с ней исчезают комментарии, вложения и решения, на которые могли ссылаться другие задачи.

На этом сквозной сценарий закончен. Требование зафиксировано в задаче, оформлено так, что его можно выполнить без расспросов, передано в работу, обсуждено в комментариях и закрыто с понятной резолюцией. Вся история решений осталась в карточке — к ней можно вернуться и через полгода.
